# 상담 신청 개인정보 영향평가 요약

## 데이터 흐름

1. 신청자가 자사 도메인 폼에 최소 정보를 입력합니다.
2. 브라우저는 같은 출처의 CSRF 토큰을 받은 뒤 HTTPS로 JSON을 전송합니다.
3. 서버는 출처, 요청 횟수, 크기, 허니팟, 필드 형식과 동의를 검증합니다.
4. 검증된 원문에 접수번호와 삭제예정일을 추가하고 AES-256-GCM으로 암호화합니다.
5. Railway 전용 영구 볼륨에는 AES-256-GCM 암호문 파일만 저장합니다.
6. 공개 읽기 API는 없으며 승인된 장치에서 필요한 항목만 오프라인 복호화합니다.
7. 90일이 지난 암호문은 서버의 일일 보존기간 작업이 삭제합니다.

## 최소 수집

| 구분 | 항목 | 이유 |
|---|---|---|
| 필수 | 상담 분야 | 담당 범위 판단 |
| 필수 | 성함 | 상담자 식별 |
| 필수 | 연락처 | 회신 |
| 필수 | 상담 내용 | 사안의 기본 범위 판단 |
| 선택 | 이메일 | 이메일 회신 선택 시 사용 |
| 미수집 | 주민등록번호·계좌·카드·비밀번호·첨부 | 첫 상담에 불필요하고 위험도가 높음 |

## 주요 위험과 통제

| 위험 | 수준 | 통제 |
|---|---:|---|
| 외부 설문·분석 업체로 원문 유출 | 높음 | 외부 폼·분석·픽셀 제거, CSP `connect-src 'self'` |
| 저장소 오구성으로 평문 공개 | 높음 | 애플리케이션 계층 암호화, 공개 조회 API 없음 |
| CSRF·자동화 대량 접수 | 중간 | SameSite 쿠키, HMAC 토큰, Origin 검증, 플랫폼 IP 제한, 허니팟 |
| XSS를 통한 폼 탈취 | 높음 | 외부 스크립트 없음, 강한 CSP, React 기본 이스케이프 |
| 과도한 보존 | 중간 | 90일 자동 삭제 |
| 배포 미리보기 코드의 저장소 접근 | 높음 | 저장 데이터가 암호문이며 production에만 복호화 키 제공 |
| 인증서 오류로 전송 보호 상실 | 높음 | Railway 관리형 HTTPS, HSTS, 일일 TLS 모니터 |

## 남은 운영 확인 사항

- Railway 계약상 실제 데이터 저장 지역과 국외 이전 고지 문구
- 개인정보 보호 담당자 연락 채널
- 상담 계약 전환 시 별도 고객기록의 보존기간과 접근권한
- 운영자 계정 MFA, 최소권한, 퇴사자 권한 회수 절차
