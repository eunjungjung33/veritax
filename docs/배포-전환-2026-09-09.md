# 운영 배포를 친구(발주자) Netlify 계정으로 일원화 (2026-09-09)

## 배경
- veritax.co.kr DNS는 처음부터 발주자 Netlify 계정(팀 "JEJ Tax & Accounting", 사이트 `capable-begonia-05d189`)을 가리키고 있었으나, 이 저장소는 2026-09-02 이후 별도 Railway 계정(seokamrock)에만 배포되고 있었다.
- 인증서는 2026-09-01 만료 상태였고, 사이트에는 환경변수가 하나도 없었다.

## 처리 내역
1. 발주자 Netlify 개인 액세스 토큰으로 API/CLI 접속 (토큰은 로컬 `땡.env` 1행, 저장소 미포함).
2. 사이트 환경변수 설정: `CONSULTATION_ENCRYPTION_KEY`, `CSRF_SECRET`(신규 생성, `땡.env` 2·3행에 보관), `CONSULTATION_KEY_VERSION=v1`, `CONSULTATION_RETENTION_DAYS=90`, `ALLOWED_ORIGINS=https://veritax.co.kr,https://www.veritax.co.kr`. Free 플랜이라 secret 플래그 없이 저장됨.
3. `POST /sites/{id}/ssl/renew`로 Let's Encrypt 인증서 갱신 → `CN=veritax.co.kr`, 만료 2026-12-07.
4. `netlify deploy --prod --build --site 0aa6be1f-…`로 2차 지시서 반영본 배포. 함수 3개(csrf, consultations 등) 포함.
5. 확인: 홈·구성원·업무영역·세무 뉴스·칼럼 개별 페이지 200, www→apex 301, `/api/csrf` 200, 교차 출처 상담 POST 403, 사이트맵 11개 URL.
6. Netlify는 디렉터리 경로를 `/insights/<slug>/`(끝 슬래시)로 301 정규화하므로 캐노니컬·사이트맵도 끝 슬래시로 통일.
7. Railway 프로젝트 `veritax`(11bad153…) 삭제, `.railway/` IaC 제거, DAST·TLS 모니터 워크플로 대상은 veritax.co.kr로 변경.

## 남은 권장 사항
- Netlify 콘솔에서 GitHub `eunjungjung33/veritax`를 사이트 소스로 연결하면 push마다 자동 배포된다(GitHub 앱 권한 승인 필요, 발주자 본인이 클릭).
- 상담 원문 복호화는 `scripts/decrypt-consultation.mjs` + `땡.env`의 키를 사용한다. 키를 분실하면 접수 내용을 복구할 수 없으니 안전한 곳에 사본을 두자.
- `docs/SECURITY-OPERATIONS.md`의 Railway 볼륨 관련 절차는 Netlify Blobs 기준으로 읽는다.
